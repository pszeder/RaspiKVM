The LE minimum on this connection is 7.5 ms, in 1.25 ms increments. Bluetooth 6.2 introduces intervals as short as 375 microseconds, but its controller/host features must be supported and negotiated by both peers. Updating Raspberry Pi OS alone does not give the Pi's Bluetooth 4.1 controller those features. LE 2M increases radio data rate; it would not itself remove the traditional 7.5 ms connection-interval floor. Small HID reports are unlikely to saturate the LE 1M data rate; scheduling, wake-up, interference and firmware report generation remain relevant.

Additional changes

The inherited A1314/A1644 filter treated every all-rollover error report as Ctrl+Shift+T. That is Chrome's reopen-tab shortcut and a plausible explanation of the unexpected browser actions reported during testing. The filter now suppresses HID keyboard error usages 1–3 and retains the last valid key state until a valid report arrives. A1314 separate Fn/Eject reports use the last valid physical key cache. Unknown report lengths are ignored. The aggregate suppressedErrorReports counter records errors without recording key values. This cannot recover an actual Fn+Shift+T chord if the keyboard reports only an ambiguous hardware error for it; unambiguous Ctrl+Shift+T remains supported.

  • The keyboard forwarding thread, named raspikey-kbd, uses nice -10, matching the mouse thread. Web and Bluetooth management threads keep normal priority. This is ordinary Linux scheduling, not real-time scheduling.
  • An optional fixed-CPU mode selects the performance governor at the CPU's existing rated maximum, 1 GHz on this Pi. It does not overclock the device. The previous governor is restored on normal shutdown, rollback or restart; a protected record in /run also allows recovery after a process crash. If another service changes the governor independently, RaspiKey does not overwrite that new choice. The mode can increase Pi power use and heat.
  • The keyboard USB endpoint is configured with interval 1, matching the mouse. On the verified high-speed USB connection that requests 125 microsecond scheduling instead of 1 ms; on a full-speed connection it requests 1 ms instead of 4 ms. Host scheduling and Bluetooth input delivery still determine actual latency. Keyboard, LED, consumer-control and mouse report descriptors are unchanged.
  • Keyboard measurements retain only aggregate counts and timings. No typed key codes, text, pointer coordinates or button values are logged.

Create /var/cache/raspikey-build/build/keyboard-baseline as raspidev, then use dev.ps1 restart to disable the keyboard priority change. Remove it and restart to enable priority -10. Create /var/cache/raspikey-build/build/fixed-cpu and restart to enable the performance governor; remove it and restart to restore the previous governor. These flags survive ordinary code updates in the developer-owned build cache. Mouse LE tuning retains its separate mouse-baseline diagnostic flag.

The keyboard's meanReadToQueueUs, readToQueueP95UpperUs and maxReadToQueueUs measure raw-report processing and USB write/queueing after the report has been read. They exclude scheduler delay before the read. meanEvdevDelayUs, evdevDelayP95UpperUs and maxEvdevDelayUs separately measure kernel evdev timestamp to observation by the keyboard thread. Evdev frames and raw reports need not correspond one-to-one; do not add the two sets of averages and call the result end-to-end latency. Histogram percentiles are bucket upper bounds. Physical key scanning, radio transport before the kernel timestamp, host USB delivery, operating-system input handling and display time are excluded.

USB maintenance and rollback

Application changes deploy without a sudo password. Updating the installed USB gadget script requires the existing explicit maintenance route, dev.ps1 setup, with one sudo authentication. It stages the change while networking remains available. A controlled dev.ps1 reboot then reconstructs the gadget and briefly disconnects only the spare. Pairings, USB serial and network MAC addresses are retained. Verify both USB intervals, Windows device error codes, SSH and USB Internet after reboot.

dev.ps1 rollback restores the previous application. It does not revert the separately installed USB gadget configuration or Bluetooth connection parameters already cached by the kernel. The keyboard descriptor is unchanged, so prior releases remain compatible with the faster USB interval.
