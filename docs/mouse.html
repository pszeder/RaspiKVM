Connect and test

  1. Select the unused Easy-Switch slot paired with the spare Pi. Use short presses to select slots; holding the button enters pairing mode.
  2. Open the spare control UI. It now shows keyboards and mice. For a fresh pairing, enable discovery, put the selected mouse slot in pairing mode, and click Pair on the MX Master 3S card. Discovery can be turned off afterward.
  3. Move the mouse and test left/right/middle clicks, vertical wheel, thumb wheel, browser Back/Forward, and the thumb button (Windows Task View, Win+Tab). Keyboard and mouse forwarding run independently; the mouse also works when the spare keyboard is disconnected.
  4. Try slow precise motion and fast sweeps. Compare the Pi slot with the normal PC slot at the same Windows pointer settings. Test with the Pi's UI closed, then open, and while typing on the spare A1314.
  5. Switch away from the test slot and back. Confirm there are no held buttons/keys and forwarding resumes. A short wake/reconnect delay is separate from motion latency while connected.

The bridge reads Linux evdev packets and sends each completed SYN_REPORT immediately on a dedicated USB HID endpoint. USB interrupt polling uses bInterval=1 (1 ms at full speed, 125 microseconds at high speed). The 50 ms poll timeout is only an idle/shutdown bound: arriving input wakes it immediately. No per-motion logging, smoothing, acceleration, or fixed batching delay is added. Signed 16-bit motion avoids clipping fast movements to 8-bit deltas. Standard vertical/horizontal detent scroll events are forwarded; duplicate high-resolution events are ignored to avoid double scrolling.

reports counts queued USB reports; lastForwardUs/maxForwardUs measure time from the kernel event timestamp to queueing the USB report. Zero before any report means no measurement yet. These numbers exclude Bluetooth transport before the kernel event and USB/Windows/display processing afterward; they are not an end-to-end latency claim. droppedFrames counts evdev overruns; the bridge resynchronizes held keys/buttons and discards invalid motion after an overrun.

All 16 standard mouse button usages are preserved. For this specific Bluetooth model (046d:b034), the captured thumb button is BTN_FORWARD (sixth button), so it additionally sends Win+Tab. Back and Forward were captured as BTN_SIDE/BTN_EXTRA. The extra keyboard/consumer HID collections forward standard key events exposed by mouse firmware without using the Apple keyboard's settings. Scroll-mode/DPI controls remain the mouse's firmware behavior; custom settings, gestures and remapping come later. No Logitech application is needed for this baseline.

Mouse responsiveness tuning

The performance implementation requests a 7.5 ms Bluetooth LE connection interval with peripheral latency zero for the paired MX Master 3S (046d:b034). It also gives only the mouse worker a standard scheduler nice value of -10 and reuses its polling storage. No real-time scheduling, motion interpolation or acceleration is added. Unsupported or rejected Bluetooth tuning does not stop forwarding. The request is applied again when the mouse reconnects. An unconfirmed initial request gets one retry; later successful controller updates to other parameters trigger a new request, limited to once per five seconds. Tests verify failures do not cause continuous retries.

The first optimized release revealed that the mouse can later negotiate back to 11.25 ms and peripheral latency 44, even after a successful 7.5 ms update. Commit d097092 handles those later negotiations. Actual controller confirmation is monitored throughout the connection, rather than treating the initial acknowledgement as permanent proof.

The spare's controller acknowledged the request and reported a successful connection update: interval 7,500 microseconds and peripheral latency zero. The worker priority was independently checked on the Pi. Shorter connection intervals and zero peripheral latency can increase mouse battery use. This targets the Bluetooth path; it does not guarantee identical behavior to Logitech's USB receiver.
