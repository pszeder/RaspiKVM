MX Master 3S: scroll mode and button shortcuts

These controls operate on the spare RaspiKVM at 192.168.137.86. The original keyboard Pi at 169.254.1.1 is unchanged. No Logitech application is required on the computer.

Use the web UI

  1. Select the mouse's spare-Pi Easy-Switch slot. Refresh the RaspiKVM page to load the new controls.
  2. Find Scroll wheel and buttons inside the MX Master 3S device card.
  3. Choose Free-spin, Ratchet (fixed steps), or SmartShift (release at speed). In SmartShift mode, choose a speed from 2 to 49; higher values require faster scrolling.
  4. Under Customize a button, choose the scroll toggle, Back, Forward, thumb/task-switcher or middle click. Choose the original action, a keyboard shortcut, or Do nothing.
  5. For a shortcut, select Ctrl, Shift, Alt and/or Win/Cmd, then a key. Click Save mouse settings and wait for Settings applied to the mouse. Changes are stored immediately on the Pi; the global Save button is not required.

The initial configuration uses free-spin and maps the button above the wheel to Print Screen. All other buttons retain their existing actions; the thumb button retains Win+Tab. A shortcut is held while its mouse button is held and released when the button is released. Changing a shortcut while held does not change that in-flight chord. Reconnection reapplies the saved wheel setting and scroll-toggle diversion. Unsaved web UI edits survive background refreshes.

How it works

A separate HID++ worker discovers the MX Master 3S Bluetooth HID device by vendor/product and its Bluetooth address. It discovers SmartShift or SmartShift Enhanced and Reprogrammable Controls feature indices, verifies the wheel state, and temporarily diverts only the top scroll-toggle control (CID 0x00C4). It leaves persistent button mappings, pointer DPI, raw motion, wheel resolution and host selection unchanged. The original scroll-toggle action clears that temporary diversion.

Diverted button edges wake the forwarding thread using eventfd. The forwarding thread merges their keyboard state with auxiliary mouse-keyboard reports on the existing mouse USB interface and writes every press/release edge separately. Physical pointer packets do not wait for HID++ command replies or web requests. No USB descriptors, sudo rules or Wi-Fi settings change for this feature; deployment uses the existing SSH-key-only flow.

Settings are stored per Bluetooth address under /var/lib/raspikey/mouse-ADDRESS.json. Invalid keys, modifier masks, modes, thresholds and unknown actions are rejected before updating the file. Saving while disconnected queues the desired configuration for reconnection. If hardware verification fails, the web UI shows the error instead of claiming that settings are applied.

# Restore the previous application if needed:
.\dev.ps1 rollback

To return specifically to the verified keyboard/mouse performance baseline before customization, deploy its retained bundle:

.\dev.ps1 deploy -Bundle .\dist\raspikey-dev-20261010T181908Z-798af77-c9a569d993b0.tar.gz

The settings endpoint returns the saved settings and actual controller status, including the verified wheel mode, diversion state and aggregate scroll-toggle press count. It does not expose typed text, pointer coordinates or button histories. A normal stop restores the top button's native reporting and releases USB keys/buttons. A link disconnect also releases forwarded input. Application rollback does not remove the saved mouse settings file; an earlier application ignores it.
